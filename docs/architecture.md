# Архитектура

Игра использует движок как внешнюю библиотеку. Обновление версии движка — отдельное изменение gitlink с проверками.
Текущий gitlink: `c69f190042cea9649f551c5196780059e892e0be` (base v1.0.0 + keyboard API, PR движка №50).
Версию хранит индекс Git/submodule, а `.gitmodules` хранит URL и путь; новую версию не получают
автоматически при обычном `git submodule update --init --recursive`.

```text
Platformer.App ──> Platformer.Core (стандартная .NET)
      │
      ├────────> Engine3D.Core
      └────────> Engine3D.OpenGL ──> Engine3D.Core
Platformer.Tests ──> Platformer.App / Platformer.Core
```

## Реализованный каркас

- Core содержит неизменяемый технический макет платформ: центр и полные размеры.
- App переводит макет в SceneObject, переиспользует один MeshData, создаёт камеру и Engine.
- `Engine.Create → Run(scene, camera, onUpdate) → Dispose` выполняются на одном потоке.
- `--help` не создаёт окно; `--smoke` закрывается после трёх показанных кадров.
- Камера смотрит сбоку на плоскость X/Y. Escape в активном окне штатно закрывает preview через RequestClose.
- CPU-тесты проверяют адаптацию координат/размеров, камеру, независимость сцен и общий mesh.

## Проектируемая архитектура игры

Это проект будущих модулей, не описание уже реализованной игры.

```text
Оконные события → Engine.Input → InputMapper → GameInput
                                          ↓
Время кадра → FixedStepRunner → GameSimulation.Step
                                   │
                         LevelDefinition + PlayerState + GameSession
                                   ↓
                         GameScenePresenter → Scene/Camera → Engine.Run render
```

| Модуль | Ответственность | Не делает |
|---|---|---|
| Core/Level | Данные платформ, spawn и согласованных областей, валидация Bounds2 | Не создаёт SceneObject и окно |
| Core/Simulation | Движение персонажа и разрешение 2D-коллизий по фиксированному шагу | Не читает клавиатуру и реальное время |
| Core/Session | Согласованные состояния/переходы игрового сеанса | Не рисует UI и не владеет GPU |
| App/InputMapper | Преобразование снимка клавиатуры в игровые команды | Не меняет позицию игрока напрямую |
| App/FixedStepRunner | Шаги симуляции, ограничение задержек, очередь одноразовых команд | Не разрешает столкновения |
| App/Presenter | Объекты сцены, материалы, синхронизация transform и камеры | Не подменяет физику визуальной геометрией |
| Tests | CPU-регрессии Core, проверки координации App, отдельный графический smoke | Не требует GPU для CPU-тестов |

До независимой реализации команда фиксирует [контракты](game-api.md): формы данных,
ошибки, шаг, допуски, порядок переходов и правила соприкосновения прямоугольников.
Обновление кадра: получить один input snapshot, накопить команды, выполнить разрешённое
число sim ticks, обновить представление, вернуть управление renderer.
Фронт нажатия потребляется один раз; отсутствие sim tick не должно терять команду.
Численные ограничения задаются в контракте после согласования требований.

Уровень неизменяем; сеанс и персонаж — изменяемое состояние симуляции. Меши/материалы
переиспользуются представлением там, где это предусмотрено; симуляция не хранит ссылки на них.
Ввод, симуляция и рендер выполняются на потоке Create; фоновые потоки не мутируют Scene.
Потеря фокуса очищает input queue и накопленное время; поведение паузы определяется T01/T02.

Ответственные и стыки — [команда](team.md), последовательность — [план](../project_plan.md).

## Клавиатурный ввод

Сигнатура callback `Action<float>` сохранена. Внутри него `engine.Input` возвращает
неизменяемый InputSnapshot с фокусом, IsDown, WasPressed и WasReleased для InputKey.
Публичный контракт не раскрывает окно или OpenTK-типы. Первый пакет активации подавляется;
при потере фокуса удержания и фронты очищаются. Повторный sim tick не должен повторять одно нажатие.
Игра должна сама очищать очередь команд/накопленное время при потере фокуса.
Полный контракт находится в `external/engine/docs/keyboard-input.md`.
Расширение добавлено в upstream по отдельному поручению через PR; обновления движка остаются отдельными задачами.
Прямые OpenTK/GL-вызовы, reflection или создание второго окна для ввода не допускаются.

## Соглашения

Правая система, Y вверх; в System.Numerics row-vector `model = scale * rotation * translation`.
Поправку глубины и загрузку матриц выполняет движок; игра её не дублирует.
GPU-ресурсами владеет Engine; игровые данные и Scene не освобождают GPU handles.
Материалы и меши разделяются только там, где их совместное использование предусмотрено.
