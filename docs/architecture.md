# Ball Adventure — архитектура 3D-игры

Статус: проект реализации, не описание готовой игры. База — три проекта .NET10;
публичные Engine3D.Core/OpenGL используются через submodule на
`c69f190042cea9649f551c5196780059e892e0be`. Движок не редактируется внутри submodule.

```text
Platformer.App → Platformer.Core (только стандартная .NET)
      ├──────→ Engine3D.Core / Engine3D.OpenGL
      └──────→ публичные API мыши, UI и аудио после отдельных upstream PR
Platformer.Tests → Core / CPU-часть App
```

Имена solution/пространств имён Platformer сохраняются, чтобы не добавлять несвязанный рефакторинг.
3D означает перемещение в X/Z и прыжок/гравитацию по Y, а не прежний фиксированный Z.

## Цикл кадра и владение

```text
Process events → InputSnapshot → InputRouter (игра или меню)
  → Camera mouse look (один раз за кадр) → GameCommand с горизонтальным yaw
  → FixedStepRunner → Session.Step → Ball/Obstacles/Coins/Finish
  → Presenter + HUD + AudioCoordinator → render
```

Core не знает клавиш, OpenTK, окна, аудио, UI, wall clock и SceneObject.
Меню/пауза не вызывают Step; фокус/смена экрана/перезапуск очищают очередь и аккумулятор.
Mouse delta не умножается на deltaSeconds и не применяется повторно на catch-up ticks.
Jump/Boost потребляются один раз и сохраняются до ближайшего tick, если его ещё не было.
Restart — переход App: выполняется один раз в текущем кадре до Step и очищает очередь/аккумулятор.
WASD преобразуется в нормализованный вектор X/Z относительно yaw камеры, не pitch.

Окно, рендер, обновление сцены, изменение cursor mode и публичный аудиоконтекст живут
на согласованном потоке Engine.Create. Engine владеет и освобождает GPU/UI-ресурсы.
App владеет игровыми данными и отдельным AudioDevice; при завершении App вызывает его Dispose,
а AudioDevice освобождает свои voices/buffers/context до завершения приложения. Пауза останавливает игровые эффекты/музыку по контракту, меню остаётся доступным.
Кэш меша сферы общий, скин меняет материал/текстуру, не ColliderRadius и не массу.

## Физика и камера

Уровень использует ориентированные прямоугольные объёмы OBB: так наклоны — настоящие
поверхности, а не набор AABB-ступенек. Сфера сталкивается с OBB через локальные координаты
и ближайшую точку; для центра внутри OBB normal выбирается по ближайшей грани с устойчивым tie-break.
Grounded определяется нормалью контакта и максимальным уклоном, а не только наличием пересечения.
Статическая геометрия не имеет отрицательного масштаба в коллайдере; ориентация — нормализованный quaternion.

Базовый sphere/OBB overlap сам по себе не защищает от туннелирования. Внутри fixed tick нужны
ограниченные подшаги с контролем перемещения (шара и вращающейся опасности), либо проверенный
sweep. При исчерпании бюджета весь tick отклоняется без частичной мутации и выдаётся диагностическая ошибка; шар не пропускается сквозь препятствие.
Тесты включают тонкий мост, большой разрешённый boost, угол/наклон, вращающуюся балку и начальное пересечение.
Шаг опасностей и сферы синхронный; нельзя проверять только положение балки в конце длинного шага.
Опасная балка переводит сеанс в Failed при контакте; полноценный обмен импульсами не требуется.

Камера: yaw без ограничения, pitch ограничен, желаемая позиция позади/выше шара.
Проверяется сегмент/сфера от target к камере против статической геометрии с защитным радиусом;
при преграде дистанция сокращается, восстановление плавное. Начало внутри объёма и нулевая
дистанция обрабатываются явно. Рендер-камера не изменяет состояние коллайдера игрока.

## Уровни, события, интерфейс

LevelCatalog хранит две явные записи с уникальными ID; одна загрузка создаёт GameSession/SessionSnapshot,
Scene и набор аудиокоманд. Повторный переход освобождает ресурсы старой сцены без создания второго окна.
Reset восстанавливает фазу опасностей, монеты, позицию/скорость/опору, boost и команды.
События имеют sequence ID и tick ID: звук монеты/финиша не повторяется при каждом render frame.
Финиш уровня1 ведёт к предложению NextLevel; после уровня2 — GameComplete. Монеты не блокируют финиш.

UI-модель игры остаётся в App (экраны, focus, выбранный пункт, громкость, skin ID).
Engine предоставляет только универсальное отображение overlay и ввод, не понятия LevelSelect/монет.
Меню доступно клавиатурой/мышью, курсор захвачен только в Running. При потере фокуса
освобождается, автоматического продолжения игры и скачка mouse delta нет.

Presenter (#7) владеет 3D-представлением; UI (#19) рисует единственный HUD по тому же snapshot.
