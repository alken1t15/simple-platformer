# Физика шара — задача #5

Реализована CPU-симуляция одной сферы по статическим OBB в `Platformer.Core`.
Она использует [Core v1](core-contract-v1.md), стандартную .NET и `System.Numerics`.
Игровое окно, ввод, Presenter, сеанс, монеты и вращающиеся опасности подключаются
отдельными задачами. Технический preview пока остаётся прежним.

## Использование

```csharp
using System.Numerics;
using Platformer.Core;

var settings = SimulationSettings.Default;
var simulator = new BallSimulator(TrainingTrack.Create(), settings);
BallState state = simulator.CreateInitialState();
BallStepResult result = simulator.Step(state,
    new GameCommand(Vector2.UnitX, JumpPressed: false, BoostPressed: false));
state = result.Ball;
IReadOnlyList<MotionSegment> path = result.Path;
```

Один вызов `Step` равен `settings.FixedStepSeconds`; реальное время не читается.
Симулятор не хранит изменяемого состояния сеанса. `BallState` — значение, `Path`
копируется в read-only коллекцию и сохраняется после следующих шагов.
При ошибке исходное состояние и ранее выданные результаты остаются неизменными.

`GameCommand.MoveWorldXZ` содержит мировой X/Z, длину не больше 1.
App нормализует диагональ и переводит ввод относительно yaw камеры в #6.
Core отклоняет длину больше `1+1e-6`, в пределах округления нормализует её.
`JumpPressed`/`BoostPressed` означают однократные фронты, а не удерживаемые клавиши;
App потребляет их один раз. Core не хранит клавиатурную историю.

## Начальное состояние и опора

`CreateInitialState` использует `level.Spawn`, радиус настроек и нулевые скорость,
boost/cooldown. Contact probe сразу определяет опору, поэтому можно прыгнуть первым tick.
Начальное проникновение до `SkinWidth` проецируется наружу; глубокое проникновение
отклоняется через `ArgumentException` с ID поверхности. Неразрешимая комбинация
контактов отклоняется при исчерпании `MaxContactIterations`.

`Step` принимает согласованное состояние из `CreateInitialState`/предыдущего результата.
Произвольно заданное состояние с проникновением глубже `PenetrationSlop` отклоняется
до вычислений: начальную проекцию нельзя скрыть телепортом внутри временного `Path`.
Радиус входного состояния должен совпадать с радиусом настроек в пределах `PositionEpsilon`.

Опора определяется расстоянием и нормалью контакта, а не флагом прошлого tick.
Минимальный зазор probe — `SkinWidth + PositionEpsilon`; удаляющаяся от поверхности скорость
не приклеивается к опоре. При `MaxSlopeRadians=50°` наклон 20° даёт опору, 60° — нет;
потолок тоже не является опорой. На допустимом наклоне без команды нет скатывания.
Движение проецируется на касательную без увеличения длины вектора скорости.

## Интегратор и столкновения

Сначала рассчитываются управляющее ускорение/торможение, прыжок и гравитация,
затем перемещение: полунеявный Euler. В воздухе горизонтальное управление умножается
на `AirControlFactor`, падение ограничено `MaxFallSpeed`. Прыжок задаёт мировую
`Velocity.Y=JumpSpeed`; повторное нажатие в воздухе не создаёт новый прыжок.
Boost меняет целевую скорость уже в tick нажатия; на опоре скорость после завершения
boost возвращается к обычной с заданным торможением/ускорением, без мгновенного обнуления.
Лишняя часть последнего tick boost переносится в cooldown. Проверка доступности
происходит по таймерам начала tick; уменьшение cooldown до нуля не активирует
отклонённое нажатие задним числом. Float-округление таймеров на сетке ticks
не добавляет лишний tick к целочисленным длительностям.

Sweep преобразует отрезок движения в локальную систему OBB. В точках пересечения
плоскостей граней меняется набор clamped координат; между ними квадрат расстояния
до объёма — квадратичная функция. Её первый входящий корень даёт контакт с гранью,
ребром или вершиной. Расширенная AABB сама по себе не считается точным коллайдером:
сфера может пройти снаружи её угла, не задев настоящий OBB.

Для движения используется защитный радиус `BallRadius + padding`, где
`padding = max(SkinWidth, 4*ULP)`; ULP берётся для максимального модуля координат
центра шара, центра OBB и его half extents. Этот численный запас нужен при больших
допустимых координатах, когда шаг float грубее SkinWidth: округление точки контакта
не должно помещать сферу внутрь поверхности. Тот же padding применяется при
проекции spawn и probe (с дополнительным PositionEpsilon). Физический Radius
и допустимая глубина проникновения не увеличиваются. На масштабе Training Track
padding равен заданному SkinWidth.
В контакте удаляется только входящая нормальная составляющая скорости; остаток
времени отрабатывается со скольжением. Почти касательная скорость округляется
в касательную плоскость или наружу так, чтобы не зациклить контакт с нулевым временем.
При равном времени контактов выбирается ordinal `SurfaceDefinition.Id`.
Для центра внутри OBB ближайшая грань выбирается по X/Y/Z, затем положительная сторона.

Каждый временной подшаг ограничен перемещением `BallRadius/4`; sweep проверяет
весь отрезок даже внутри подшага. `MaxCollisionSubsteps` ограничивает число подшагов,
`MaxContactIterations` — число разрешаемых контактов в каждом подшаге.
`Path` содержит фактические отрезки до контактов и после изменения направления,
покрывает весь [0,1] без временных зазоров, включая неподвижные интервалы.
Это путь шара; проверка движения опасности вдоль этих интервалов принадлежит #20.
Ошибки бюджета/неразрешённое проникновение дают `InvalidOperationException`
с ID поверхности/уровня и диагностикой; частичный результат не выдаётся.

## Настройки и авторские проверки

Поддержаны поля и индивидуальные диапазоны `SimulationSettings` из Core v1.
При создании дополнительно проверяется, что максимальная совмещённая скорость
`sqrt((MoveSpeed*BoostMultiplier)² + MaxFallSpeed²)` укладывается в бюджет подшагов.
Проверяются также соотношения SkinWidth/Radius, PositionEpsilon/SkinWidth,
PenetrationSlop и MaxFallSpeed/JumpSpeed. Некорректные настройки отклоняются с именем
параметра. Скорость произвольно переданного состояния тоже проверяется по бюджету tick.
Бюджет вращающейся опасности проверяется при её интеграции в #20/#8.

| Пример | Результат/ориентир |
|---|---|
| Default: radius 0.5, speed 4.5, boost 1.8, gravity 18, jump 6, dt 1/120 | Общий набор для уровней; cooldown 3 с после boost 1 с |
| Покой в воздухе, AirControlFactor=1, команда +X | ΔvX=1/6, Δx=1/720 за первый tick |
| Прыжок с плоскости, default | Дискретная сумма даёт подъём около 0.975, не непрерывную оценку 1.0 |
| Radius 0.1/0.5/2 и dt 1/240, 1/120, 1/30 | Посадка на тонкий мост; для матрицы выбран бюджет 128 |
| Radius 0.1, speed 20, boost 3, dt 1/30 | Бюджет 32 недостаточен; 128 достаточен при MaxFallSpeed=30 |
| Координаты около ±9000, radius 0.3, SkinWidth 1e-4 | Посадка без проникновения с учётом ULP; отдельно проверена начальная неглубокая проекция |

Тесты: [геометрия](../tests/Platformer.Tests/SphereGeometryTests.cs),
[симулятор](../tests/Platformer.Tests/BallSimulatorTests.cs),
[настройки](../tests/Platformer.Tests/SimulationSettingsTests.cs).
Геометрические ориентиры — аналитические face/edge/corner; sweep дополнительно
сравнивается с независимым численным поиском по выпуклой функции расстояния.
Базовый векторный допуск — 1e-5; время контакта проверяется с допуском 1e-6,
для повёрнутого примера — 2e-6, для численного поиска — 2e-5 доли tick.
В CPU-проверках стыков Training Track высотный допуск — 2e-4.

Проверены подъём по наклону Training Track, переход на верхнюю площадку, мост,
сход с него и обычный прыжок между площадками без boost на default settings.
Эти CPU-сценарии не означают ручное прохождение игры: ввод, камера, рендер, второй
уровень, события сеанса и движущиеся опасности требуют своей интеграции и QA.
