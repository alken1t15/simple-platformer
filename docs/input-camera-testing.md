# Проверка управления и камеры #6

Автоматические проверки стыка host описаны в [input-camera.md](input-camera.md).
Требования ручной приёмки остаются в [issue #6](https://github.com/alken1t15/simple-platformer/issues/6)
и [общих сценариях](acceptance.md); этот документ даёт команды воспроизведения.

## CPU и ограниченный запуск

После restore/build по README:

```sh
dotnet test Platformer.sln -c Release --no-build
dotnet run --project src/Platformer.App -c Release --no-build -- --help
dotnet run --project src/Platformer.App -c Release --no-build -- --play --smoke
```

Smoke завершается после трёх кадров, не использует игровой ввод/Step и не захватывает мышь.
Отдельно сохраняются smoke технической сцены и двух скинов Presenter из README.
GameplayHostTests использует настоящую физику/сеанс, включая terminal transition
в первом tick длинного кадра; два тестовых уровня проверяют смену Presenter в одной Scene.
Они не являются поставляемой второй локацией.

## Автоматический native X11

Нужны Linux, .NET 10, X11-дисплей с OpenGL 3.3, системные libX11/libXtst и Python3.
Python-пакеты не нужны; ImageMagick при наличии сохраняет снимок сцены.
Запускать на отдельном тестовом дисплее: драйвер синтезирует клавиши/мышь,
переключает фокус и меняет размер своего игрового окна.
В finally отпускает свои клавиши, завершает процесс и восстанавливает фокус/указатель.

```sh
XDG_SESSION_TYPE=x11 python3 scripts/check_gameplay_x11.py
```

Для software-прогона в окружении с Xvfb:

```sh
LIBGL_ALWAYS_SOFTWARE=true XDG_SESSION_TYPE=x11 xvfb-run -a -s '-screen 0 1280x800x24' python3 scripts/check_gameplay_x11.py
```

Драйвер проверяет все сопоставленные клавиши, левую кнопку/позицию указателя,
Start/capture, реальное движение, yaw/pitch и yaw-relative WASD, resize,
pause/Continue, R, прыжок и оба Shift, фронты без повторов, focus loss/gain,
удержание W дольше autorepeat и обязательный release/new press, штатный выход.
Поток `--trace-input` и снимок сохраняются в игнорируемом `artifacts/input-camera`;
другой каталог задаётся `--output`.

Это синтетический ввод и прямое переключение X11-фокуса. Он не доказывает работу
физической мыши, Alt-Tab конкретного WM, Wayland, повышенного DPI или FPS.

## Оставшаяся ручная приёмка

Запустить `--play`, оставить терминал с подсказками видимым. Проверить:

- Enter/Space запускает уровень и захватывает мышь. WASD ориентирован по камере,
  Space прыгает с опоры, любой Shift даёт разовый boost, R сбрасывает попытку/монеты/камеру.
- Мышь вверх поднимает взгляд, мышь вниз опускает; вращение без переворота.
  На мосту/наклоне и у статической стены камера
  сокращает расстояние и плавно возвращается. Удержание клавиш не повторяет фронты.
- Escape освобождает курсор и ставит паузу. Enter явно продолжает, первый mouse delta
  не скачет. Удержанные при переходе клавиши работают после отпускания и нового нажатия.
- Настоящий Alt-Tab с удержанием W/Space/Shift ставит паузу и освобождает курсор.
  Возврат не продолжает игру; после Enter удержания требуют release/new press.
- Resize/сворачивание/восстановление и доступные DPI-масштабы сохраняют ориентацию,
  пропорции и единицы mouse delta. Отсутствующий DPI-стенд отмечать как непроверенный.
- Падение даёт Failed, повтор запускает новую попытку; финиш прекращает тики,
  Enter завершает доступный маршрут. Полное прохождение двух локаций ждёт #21.

Меню/HUD/звук в этом стенде отсутствуют. Консольные подсказки не считаются их приёмкой.
Результат ручного прогона пока не зафиксирован; автоматические проверки не заменяют его.

## Проверенный этап PR — 06.11.2026

Release-сборка на SDK 10.0.114 прошла без предупреждений и ошибок; CPU-тесты — 202/202,
без пропусков. Help без окна, документы и diff прошли проверки.
На отдельном Xephyr/X11 с software OpenGL прошли полный native-драйвер и четыре
трёхкадровых smoke: техническая сцена, Presenter classic-blue, orange/overview и `--play`.
Диагностика `--play --smoke` подтвердила Normal и отсутствие Step во всех кадрах.
Снимок настоящего сеанса просмотрен; FPS/физическое устройство/WM Alt-Tab/HiDPI
не измерялись и не принимаются этим результатом. Удалённые проверки выполняет CI PR.

Вертикальное управление проверено отдельно: мышь вверх поднимает направление взгляда,
мышь вниз опускает. Два CPU-сценария воспроизводили инверсию до исправления знака.
После исправления прошли вся CPU-suite, полный X11-прогон с обоими направлениями
мыши и повторный `--play --smoke` (три кадра, Normal, без Step).

В этот этап включены найденные при игре дефекты: упор у прыжкового зазора и
ориентация/преждевременный trigger финиша. GapCollisionTests и два теста
GameScenePresenterTests воспроизводили ошибки до исправлений; подробности —
[физика](ball-physics.md#регрессия-упора-в-прыжковый-зазор) и [уровень](training-track.md).
