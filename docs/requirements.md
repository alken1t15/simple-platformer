# Требования и решения по игровому MVP

## Подтверждено

- Учебный 2D-платформер на C#/.NET 10 с существующим Simple 3D Engine.
- Игровая плоскость X/Y, фиксированная Z, камера сбоку.
- Core без графических зависимостей; ввод/окно/представление в App.
- Командная разработка по [распределённым задачам](../project_plan.md), не реализация всей игры одним агентом.

## Решения для задачи требований

Это предложения для обсуждения, а не утверждённое поведение.

| Вопрос | Предлагаемая минимальная версия | Что нужно зафиксировать |
|---|---|---|
| Управление | A/D или Left/Right, Space — прыжок, R — перезапуск, Escape — выход | Принятые клавиши и действия, поведение одновременных направлений |
| Движение | Постоянная горизонтальная скорость, гравитация, одиночный прыжок с опоры | Параметры и их допустимые диапазоны, управление в воздухе |
| Коллизии | Неподвижные прямоугольные платформы, пол/стены/потолок | Касание границ, начальное пересечение, ограничения скорости/шага |
| Уровень | Один короткий маршрут от spawn к финишу | Схема, размеры, достижимость и минимальный сценарий прохождения |
| Сеанс | Падение возвращает на старт, финиш завершает прохождение, R начинает заново | Условия и приоритет переходов, полный состав сбрасываемого состояния |
| Камера | Боковая перспектива, короткий уровень помещается целиком | Нужна ли прокрутка, поведение resize, область видимости |
| Фокус | Пауза с сохранением состояния, очередь команд/время очищаются | Возврат без скачка симуляции и отложенного прыжка |
| Обратная связь | Цвет/геометрия объектов и понятная инструкция | Способ показать начало/финиш/перезапуск; текстовый UI движком не предоставлен |
| Платформы | Windows и Linux как кандидаты для проверки запуска | Реальные целевые ОС и доступные стенды; CI не заменяет ручной прогон |

Без отдельного согласования не добавляются враги, звук, редактор, несколько уровней,
геймпад, сохранения и дополнительная система анимации.
Задача требований фиксирует принятые решения и сценарии приёмки; затем задача API
задаёт сигнатуры, допуски и ошибки. Реализация начинается после этих результатов.
Завершение этих задач не требует вымышленных сроков или уже реализованной игры.
