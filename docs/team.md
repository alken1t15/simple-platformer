## Владение задачами

У каждой issue один владелец результата и два reviewer-кандидата, отличных от владельца.
Для задач Team Lead reviewer-кандидаты не назначаются. Кандидаты в описании задачи —
план будущего ревью, а не отправленные review requests.
Если фактический автор PR отличается от владельца issue, исключите автора из reviewers.
Для чужих PR требуются два независимых человеческих Approve; AI-ревью не учитывается.
Для собственных PR `alken1t15` reviewers не назначаются, CI сохраняется.

Распределение, ссылки и зависимости — в [плане](../project_plan.md) и GitHub issues.
GitHub Assignee отражает фактическое назначение, строка Owner в issue сохраняет план
на случай, если приглашение участника ещё не принято. Не выдавайте pending invitation за полученный доступ.
