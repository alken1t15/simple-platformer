# Training Track — данные первой локации

Результат задачи #4: `TrainingTrack.Create()` возвращает неизменяемый `LevelDefinition`
с ID `level1`. Источник геометрии — [TrainingTrack.cs](../src/Platformer.Core/TrainingTrack.cs),
без JSON, ресурсов движка и дублирования размеров для рендера. Физика и Presenter
должны читать `SurfaceDefinition.Bounds`: полный scale равен `2 * HalfExtents`,
позиция — `Center`, поворот — `Orientation`. Это ещё не подключённый игровой уровень.

## Маршрут и поверхности

Все координаты мировые, Y вверх. Схема сверху (положительный Z вниз):

```text
                         +X →
Z=0     [start] → [ramp] → [upper-platform]
                                  ↓
Z=2..8                         [bridge]
                                  ↓
Z=10                        [jump-takeoff]
                             зазор Z=12..13
Z=15    [finish] ← [boost] ← [jump-landing]
```

Пусть `h = 3 * tan(20°) ≈ 1.09191`. Толщина всех дорожек — 0.4.
Размеры таблицы полные; `top` — высота верхней горизонтальной грани.
Названия участков ниже — фактические `SurfaceDefinition.Id`.

| ID | Центр X/Z | Размер X/Z | top / поворот |
|---|---|---|---|
| `start` | 0 / 0 | 4 / 4 | 0 |
| `ramp` | см. формулу ниже | 3/cos(20°) / 2.5 | вращение +20° вокруг Z |
| `upper-platform` | 7 / 0 | 4 / 4 | h |
| `bridge` | 7 / 5 | 1.4 / 6 | h |
| `jump-takeoff` | 7 / 10 | 4 / 4 | h |
| `jump-landing` | 7 / 15 | 4 / 4 | h |
| `boost-straight` | 1 / 15 | 8 / 2.5 | h |
| `finish-platform` | −5 / 15 | 4 / 4 | h |

У горизонтальных дорожек `Center.Y = top − 0.2`. У наклона верхние точки
центральной линии — `(2, 0, 0)` и `(5, h, 0)`. Его центр:
`(3.5, h/2, 0) − 0.2 * Rotate(UnitY, Orientation)`.
Это сохраняет высоту стыков с обеими площадками; поворот относительно центра
без смещения вниз дал бы выступы. Разрыв прыжка — ровно 1 по Z при равных высотах;
разгон и торможение доступны на посадочной/финишной площадках.
Невидимых стен и удерживающих бортиков нет; опасности первой локации отсутствуют.

`Spawn = (−1, 0.501, 0)` — над стартом для радиуса 0.5 и `SkinWidth = 0.001`.
Это геометрический ориентир под параметры Core v1. Полную опору и допустимое
начальное проникновение проверит `BallSimulator.CreateInitialState` из #5,
а не конструктор `LevelDefinition`.
`KillY = −5.4`: самая нижняя вершина дорожек имеет Y=−0.4, запас равен 5.
Зона `Finish`: центр `(−5, h+0.75, 15)`, локальные половины размеров `(1.5, 0.75, 0.1)`,
поворот +90° вокруг Y. Проём рамки лежит в мировой плоскости Y/Z поперёк последней
прямой, по которой шар катится к −X. Тонкая область срабатывания находится у рамки,
а не у входа на финишную площадку. Это trigger без физической стены.

## Монеты

Радиус всех монет — 0.2. Их десять, по две на каждое упражнение.
Для позиций над наклоном прибавление 0.8 задано по мировой Y.

| ID | Center X / Y / Z |
|---|---|
| `coin-start-1` | −0.3 / 0.8 / −0.65 |
| `coin-start-2` | 0.9 / 0.8 / 0.5 |
| `coin-ramp-1` | 2.9 / 0.9*tan(20°)+0.8 / 0 |
| `coin-ramp-2` | 4.1 / 2.1*tan(20°)+0.8 / 0 |
| `coin-bridge-1` | 7 / h+0.8 / 4 |
| `coin-bridge-2` | 7 / h+0.8 / 6 |
| `coin-jump-1` | 7 / h+0.8 / 11 |
| `coin-jump-2` | 7 / h+0.8 / 14 |
| `coin-boost-1` | 3 / h+0.8 / 15 |
| `coin-boost-2` | 0 / h+0.8 / 15 |

Монеты не пересекают spawn, дорожки и финиш. Монеты прыжка размещены на
взлётной и посадочной площадках, без необходимости ловить их над пропастью.
В данных нет требования собрать монеты для финиша; правило завершения реализуется в #8.

## Контракт и проверки

`OrientedBox` переводит точки между системами координат и находит ближайшую точку
объёма через local clamp. Ориентации и оси нормализуются. Определения поверхностей,
монет и опасностей неизменяемы; списки уровня копируются и выдаются как read-only.
ID сравниваются ordinal, уникальны совместно для surfaces/coins/hazards.
Проверяются null, пустые ID, NaN/Infinity, диапазоны координат/размеров и нормы.
Уровень не сортирует входные списки; геометрия по ID не зависит от их перестановки.
Пустые coins/hazards допустимы; валидация формы данных не доказывает проходимость.

Авторские CPU-тесты: [LevelDefinitionTests.cs](../tests/Platformer.Tests/LevelDefinitionTests.cs),
[TrainingTrackTests.cs](../tests/Platformer.Tests/TrainingTrackTests.cs).
Они проверяют OBB на горизонтальных и наклонных гранях, пределы чисел/норм,
защиту коллекций, перестановку поверхностей, стыки, зазор, spawn, KillY и статическую
достижимость монет сферой радиуса 0.5 над опорой.

В #5 добавлены [CPU-проверки физики](ball-physics.md) наклона/стыков, моста,
схода с него и обычного прыжка через зазор на настройках по умолчанию.
Реальное прохождение с вводом/камерой, совпадение отрисовки с коллайдером и видимость
маршрута ждут подключения App/Presenter и интеграции/QA #9/#11.
Код App и старый технический preview этим изменением не переключаются.
